# Prowl

Search over Northwestern undergraduate research: SURG grants and Undergraduate Research Expo projects.

## Roadmap

- [x] Exact search with single or double quotes around a phrase.
- [ ] Stop expanding acronyms that an abstract coins for itself.
  - The cards' `acronyms` faithfully echo every acronym an abstract defines, including ones its authors coined for that abstract alone. expo-2022-087 writes "antibiotic resistance (AR)", so `backend/search.py` expands "ar" to antibiotic resistance in every query, though AR is not a standard acronym for it (if anything, it is augmented reality or autoregressive). Likewise BA (balanced accuracy, expo-2026-130), PIC (persistent inward current, expo-2025-002) and AB (audiologist best-practices, expo-2026-201).
  - The vote between cards (`MIN_SHARE`) cannot catch this: 1,001 of the 1,334 expanded keys rest on a single card, so nothing outvotes them. Short keys are the most exposed; 92 of the 140 two-character expansions are single-card.
  - Handle carefully: the same single-card path expands real acronyms the query model cannot read (CDMS, T2DM, tRNA, iPSC, IRB, FERPA), and f272701 showed those expansions matter. Options: have the card prompts keep only acronyms in standard use, or judge each key's standard meaning once, separately from the cards.
  - The 2012-2019 Expo abstracts will add more (expo-2014-061 coins AR for anti-reflection).
- [ ] Mark the matched words and phrases in results for every query, not only quoted phrases. The guiding principle is that results should explain themselves.
  - Today `Marked` in `frontend/src/App.tsx` highlights only quoted phrases.
  - First, mark BM25 matches: the query words (by stem) wherever they appear in the title, people, advisors and abstract. This is cheap.
  - Also mark lexical matches of query expansions: when an acronym in the query is expanded ("qpcr" to "qPCR, quantitative polymerase chain reaction"), mark the expansion where it appears, since today only the dense side sees it and an abstract that spells it out would otherwise show no mark.
  - Name matches matter most. When `people.People.pins` puts a person's projects first, mark the name that matched, so a visitor sees why a project they didn't search for by topic came first, and which of several people with that name it is.
  - Reach goal, likely worth doing: dense matches often share no words with the query, so also mark the abstract sentence closest to the query, shaded more lightly than exact matches. Embed abstract sentences offline and score them against the query vector already computed.
  - Further reach, worth considering: explain matches that came from a card. "Spectral geometry" finds the SURG grant "Can one hear the shape of a clarinet?" only through its card's concepts and generated queries, and the card shows just the title, year and author, so there is nothing to mark. A quiet line such as "Matched on: spectral geometry (inferred from the title)", with the gloss in a tooltip, would name the card term that actually caused the match (the winning generated query in the dense score, or the card fields BM25 hit).
    - Show it only when card terms were decisive and the match is strong, never styled as data, so cards still never pass for real data.
    - It would also make bad cards visible, to be fixed in `data/card_overrides.jsonl`.
- [ ] Filter results by a set of disciplines (multi-select).
- [ ] Autocomplete in the search box.
  - Suggest completions as a visitor types: people's names (from `backend/people.py`), project titles, disciplines and common topic terms.
  - Results already update as you type, so suggestions should help finish a query, not replace the live results.

- [ ] A fast reranker that adds barely any latency (server p50 is about 49ms).
  - Tried on an M5 Pro CPU (4 threads), reranking the hybrid top-k over 21 negation and 27 general hand-written queries. Every target was already in the baseline top 5, so these queries only test reordering.
  - Best affordable option: `cross-encoder/ettin-reranker-32m-v1` on title + gloss (not the abstract), k=20, at +53ms p50 (the 17m model: +21ms). Neither clearly beat the baseline (32m did better on 7 negation queries and worse on 5).
  - Only the 400m and 1b Ettin models clearly won (1b moved negation hit@1 from 10 to 16), but they cost 0.9-2.4s. `mxbai-edge-colbert` costs about 2ms at query time but did not help. Full abstracts were worse and 4-5x slower than glosses.
  - A reranker can lift a target the baseline buries, but by matching wording, not knowledge. For "how do roundworms sense heat", "Temperature Sensation in C. alexandriana" (a title-only SURG grant) comes 7th in the hybrid ranking, behind C. elegans projects; every Ettin size from 17m to 1b reranks the top 50 so it comes 1st or 2nd, on titles or on card text. But the 150m and 1b models also put it 1st for fish, snakes, nematodes and plants, so they match "sense heat" to "Temperature Sensation" and ignore the organism. A reranker that reads only titles cannot know what a title does not say.
  - Next: a bigger eval, and a latency measurement on Railway.
- [ ] Bias ranking toward results with an abstract.
  - On "astronomy research i can do with public data", short title-only SURG cards with generic glosses held 5 of the dense top 7, ahead of abstract-backed Expo projects that fit better (Das-Ghosh's Local Bubble project came 13th, Clarendon's [OI] project 16th).
  - Against vague queries, abstract bodies are diluted by specifics (with voyage-4-nano, Das-Ghosh scored 0.422 on full text vs 0.479 on title + fields + concepts alone), while title-only glosses are field-level definitions. One candidate fix is a third vector per project built from title + fields + concepts.
  - BM25 length normalization also favours the ~33-token title-only cards.
- [ ] Bake in some recency bias.
  - Once the older sources above are indexed (Expo 2012-2019, SURG 2010-2019, NURJ from 2003, Economics theses from 2000), research goes back decades, and today ranking ignores dates entirely, so a 2004 paper and a 2025 project of equal relevance rank the same.
  - The usual approach is a decay function of age folded into the relevance score, as in Elasticsearch's [`function_score`](https://www.elastic.co/guide/en/elasticsearch/reference/current/query-dsl-function-score-query.html) decays (gauss, exp or linear, tuned by `scale`, `offset` and `decay`). Adding a constant 1 to the decay makes it a multiplier between 1 and 2, so old but strong matches are nudged down rather than buried. Here that would multiply the RRF `fused` score in `backend/search.py`, with age taken from a project's latest year.
  - Web engines apply freshness per query ("query deserves freshness"): strongly for news-like queries, barely for evergreen ones. Google Scholar keeps relevance as the default and offers a separate recent-first mode that it says ranks recent papers "the way researchers do" rather than sorting by date alone. The year filter already covers explicit intent, so a mild default bias may be enough.
- [ ] Study a relatively open search engine like DuckDuckGo and how it handles the gamut of search issues (recency among them), and borrow what fits.
